Azure Bastion Deployment to Remove Public RDP Access

Design Architecture — Secure administrative access using Azure Bastion and private VM networking

Architecture Overview

The proposed architecture uses Azure Bastion as the managed administrative access layer for a Windows Virtual Machine. The VM is deployed inside an Azure Virtual Network and is accessed through private network connectivity. The final design removes the need for a public IP address on the VM for RDP administration.

Architecture Components

  • Administrator / Azure Portal: Starts the remote management session through the Azure Portal.
  • Azure Bastion: Provides managed RDP/SSH access and acts as the controlled public entry point for administration.
  • Azure Virtual Network: Provides the private network boundary connecting Bastion and the VM.
  • AzureBastionSubnet: Dedicated subnet used by Azure Bastion.
  • Workload / VM Subnet: Contains the Windows VM and its private network interface.
  • Windows Virtual Machine: Target workload accessed through a private IP.
  • Network Security Group: Controls network traffic and helps prevent unnecessary public RDP exposure.

Secure Connection Flow

  1. The administrator signs in to the Azure Portal.
  2. The administrator selects the Windows VM and chooses the Bastion connection option.
  3. Azure Bastion provides the managed RDP session.
  4. Bastion reaches the VM through private VNet connectivity.
  5. The VM does not require a direct public IP for this administrative path.
  6. NSG rules provide additional network-level traffic control.

Existing vs Proposed Architecture

Aspect Traditional Direct RDP Proposed Bastion Design
VM Public IP May be required Not required for Bastion access
RDP Exposure Potential direct Internet exposure No direct public RDP endpoint on VM
Access Path Internet → VM Portal → Bastion → Private VM
Network Model Public endpoint may be used Private workload + dedicated Bastion subnet
Security Goal Remote administration Remote administration with reduced VM public exposure

Expected Result

The completed implementation should demonstrate that the Windows VM has no direct public IP, direct public RDP exposure is removed, Azure Bastion is deployed and operational, and the administrator can establish an RDP session through Bastion.
